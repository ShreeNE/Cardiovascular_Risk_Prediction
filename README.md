# CorVita // AAA RPG Cardiovascular Risk & Coronary Assessment Simulator

A sterile, medical-grade risk simulator inspired by the **Hogwarts Legacy** AAA RPG Character Creator UI, built with **Next.js 16**, **React 19**, **Tailwind CSS**, **shadcn/ui**, **Framer Motion**, and **Three.js**.

## 🧠 Machine Learning Engine (`model/`)

A production-grade, leak-free clinical machine learning pipeline trained on the **Z-Alizadeh Sani** coronary artery disease dataset (`extention of Z-Alizadeh sani dataset.xlsx`, N=303 patients, 54 raw clinical features).

### 1. Strict Anti-Leakage Protocol
To preserve strict clinical validity and prevent catastrophic data leakage:
- **Catheterization Targets Excluded**: `Cath`, `LAD`, `LCX`, and `RCA` represent ground-truth coronary angiography outcomes and are **strictly excluded** from the feature matrix $X$.
- **Zero In-Fold Contamination**: Imputation, scaling, and SMOTE (Synthetic Minority Over-sampling Technique) are fit **strictly inside each training fold** during cross-validation, guaranteeing no validation data leaks into training.

### 2. Feature Engineering & Clinical Biomarkers
In addition to 53 processed clinical features, 14 domain-validated cardiovascular biomarkers are engineered in `model/preprocessing.py`:
1. **Atherogenic Index**: $\text{LDL} / \text{HDL}$ ratio
2. **Triglyceride-to-HDL Ratio**: $\text{TG} / \text{HDL}$ (surrogate marker for atherogenic dyslipidemia)
3. **Neutrophil-to-Lymphocyte Ratio (NLR)**: Systemic inflammation biomarker
4. **Platelet-to-Lymphocyte Ratio (PLR)**: Thrombotic risk marker
5. **Rate-Pressure Product (RPP)**: $(\text{BP} \times \text{PR}) / 100$ (myocardial oxygen demand)
6. **Pulse Pressure (PP)**: $\text{BP} - \text{DBP}$ surrogate for arterial stiffness
7. **Ventricular Efficiency Ratio**: $\text{EF-TTE} / (\text{Region RWMA} + 1)$
8. **Composite Vascular Risk Burden**: Additive index of Hypertension, Diabetes, Smoking, Dyslipidemia, and Family History
9. **ECG Ischemic Burden Score**: Aggregated ST elevation, ST depression, T-inversion, Q-waves, and Poor R Progression
10. **Age-Stratified Angina Interaction**: $\text{Typical Chest Pain} \times (\text{Age} / 50)$

### 3. Soft Voting Ensemble Architecture
Individual classifiers vary across coronary targets due to non-linear vessel geometry. To maximize generalization and stability, a calibrated **Soft Voting Ensemble Classifier** is trained for each target:
- **Gradient Boosting Classifier**: `n_estimators=200`, `learning_rate=0.03`, `max_depth=4`
- **XGBoost Classifier**: `n_estimators=200`, `learning_rate=0.03`, `subsample=0.85`
- **Random Forest Classifier**: `n_estimators=300`, `max_depth=6`, `min_samples_split=4`
- **Extra Trees Classifier**: `n_estimators=300`, `max_depth=7`, randomized split thresholds

Voting weights are optimized per target (e.g., $0.35 \times \text{GB} + 0.35 \times \text{XGB} + 0.15 \times \text{RF} + 0.15 \times \text{ET}$) to maximize ROC-AUC.

### 4. 5-Fold Stratified Cross-Validation Benchmarks

| Target | Clinical Outcome | Overall Accuracy | Precision | Recall | F1-Score | Mean ROC-AUC | Overall ROC-AUC |
|:---|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| **Cath** | Overall CAD (≥50% Stenosis) | **87.13%** | **89.33%** | **93.06%** | **0.912** | **0.920** | **0.916** |
| **LAD** | Left Anterior Descending Artery | **76.90%** | **80.23%** | **80.23%** | **0.802** | **0.850** | **0.840** |
| **LCX** | Left Circumflex Artery | **67.99%** | **59.32%** | **58.82%** | **0.591** | **0.740** | **0.733** |
| **RCA** | Right Coronary Artery | **67.66%** | **57.55%** | **53.51%** | **0.555** | **0.724** | **0.723** |

*Note: Cath achieves up to 95.8% ROC-AUC on individual cross-validation folds.*

### 5. Explainable AI (SHAP TreeExplainer)
For every inference request, the pipeline evaluates exact feature attributions using **SHAP (SHapley Additive exPlanations)** TreeExplainer:
- **Positive Drivers**: Factors actively increasing stenosis risk (e.g., Typical Angina, ST Depression, Diabetes, High RPP).
- **Protective Factors**: Factors reducing patient risk (e.g., Normal EF-TTE, high HDL, absent RWMA).
- Computed attributions are returned directly in the REST response and visualized in the frontend risk inspection panel.

## ⚡ FastAPI Inference Microservice (`model/api.py`)

A production REST API serving real-time patient evaluations:

| Method | Endpoint | Description |
|:---|:---|:---|
| `GET` | `/` | API service metadata and route directory |
| `GET` | `/health` | Model health status, loaded targets, and SHAP availability |
| `GET` | `/features` | Feature schema with raw and engineered feature names |
| `GET` | `/metadata` | Full cross-validation metrics, confusion matrices, and pipeline configuration |
| `POST` | `/predict` | Real-time single patient prediction with SHAP explanations |
| `POST` | `/predict/batch` | High-throughput batch patient predictions |
| `GET` | `/docs` | Interactive Swagger UI API documentation |

### Sample Inference Request

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
    "Age": 62,
    "Sex": "Male",
    "Weight": 85,
    "Length": 172,
    "BMI": 28.7,
    "DM": 1,
    "HTN": 1,
    "Current Smoker": 1,
    "Typical Chest Pain": 1,
    "St Depression": 1,
    "EF-TTE": 40
  }'
```

## 🚀 Running the Project

### 1. Start the FastAPI ML Backend
```bash
# From project root:
python3 model/run_server.py
# Or directly via uvicorn:
PYTHONPATH=. python3 -m uvicorn model.api:app --host 0.0.0.0 --port 8000 --reload
```
API Documentation will be available at [http://localhost:8000/docs](http://localhost:8000/docs).

### 2. Start the Hogwarts Legacy-Inspired Frontend
```bash
cd frontend
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser. The frontend includes a live connection badge (`ML Engine: Online`) that communicates directly with the FastAPI backend and seamlessly falls back to local clinical heuristics if offline.

### 3. Re-training the Pipeline
To re-train the models with custom parameters or new data:
```bash
python3 model/train.py
```
Trained artifacts and evaluation reports are automatically serialized to `model/saved_models/`.
